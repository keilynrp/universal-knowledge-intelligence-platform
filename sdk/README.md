# UKIP SDK

Generated client artifacts for the UKIP API.

## What is here today

| Path | Status |
|---|---|
| `openapi.json` | ✅ Committed baseline, regenerated by `scripts/generate-sdk.mjs`, drift-gated in CI |
| `typescript/` | ✅ Generated with `@hey-api/openapi-ts` — full coverage (all 420 operations) |
| `python/` | ✅ Generated with `openapi-python-client` — see [Python fidelity note](#python-fidelity-note) |

The **contract** is stable and gated. Both **clients** are generated wholesale from
`openapi.json` and committed; see [Generating the clients](#generating-the-clients)
to regenerate.

## Installing and using

The clients are **not published to npm or PyPI**. Consume them by git reference
or local path.

### TypeScript

`sdk/typescript` is TypeScript source with no `package.json` and no runtime
dependencies (the fetch client is generated inline), so it is vendored rather
than installed:

```bash
git clone --depth 1 https://github.com/keilynrp/universal-knowledge-intelligence-platform.git ukip
cp -r ukip/sdk/typescript ./ukip-sdk
```

The shared `client` is not re-exported from the index; import it from
`client.gen`:

```ts
import { getEntities } from "./ukip-sdk";
import { client } from "./ukip-sdk/client.gen";

client.setConfig({
  baseUrl: "https://api.ukip.inbounduxd.com",
  headers: { Authorization: `Bearer ${token}` }, // JWT or a ukip_ API key
});

const { data } = await getEntities();
```

### Python

```bash
pip install ./sdk/python
# or by git ref
pip install "git+https://github.com/keilynrp/universal-knowledge-intelligence-platform.git#subdirectory=sdk/python"
```

```python
from ukip_universal_knowledge_intelligence_platform_client import AuthenticatedClient
from ukip_universal_knowledge_intelligence_platform_client.api.entities import get_entities

client = AuthenticatedClient(
    base_url="https://api.ukip.inbounduxd.com",
    token=token,  # JWT or a ukip_ API key; sent as "Authorization: Bearer <token>"
)
entities = get_entities.sync(client=client)
```

## Regenerating

```bash
node scripts/generate-sdk.mjs           # rewrite sdk/openapi.json
node scripts/generate-sdk.mjs --check   # fail if the committed spec is stale
```

**Route handler docstrings are part of the spec.** FastAPI publishes them as
operation `description` fields, so editing one drifts the committed spec and
trips the gate — correctly, since those descriptions reach generated client
documentation. If CI reports drift on a change that "only touched comments",
this is why: rerun the generator and commit the result.

The spec is read directly off the FastAPI app object — no server, no port, no
database, no lifespan — so the CI gate stays cheap and does not depend on a
healthy runtime.

## Operation IDs are the public method names

Generated clients turn each `operationId` into a method name, which makes those
identifiers part of the external contract. They are derived from **HTTP method
+ path**, never from Python function names:

```
GET    /users/me            ->  get_users_me
POST   /api-keys            ->  post_api_keys
DELETE /api-keys/{key_id}   ->  delete_api_keys_by_key_id
GET    /embed/{token}/data  ->  get_embed_by_token_data
```

A path or method change *is* a breaking API change and should rename the client
method. An internal refactor is not, and cannot. `backend/openapi_ids.py` holds
the rule; `backend/tests/test_openapi_operation_ids.py` pins it.

The trade-off is mechanical, sometimes long names. That is the cost of
decoupling the public surface from internal naming, and it is improvable per
route with an explicit `operation_id=` on the decorator.

## Authentication

Every endpoint takes `Authorization: Bearer <token>`, where the token is either
a JWT from `POST /auth/token` or a `ukip_` API key. One header, two credential
kinds — the backend branches on the `ukip_` prefix.

### API key scopes

Keys carry `read`, `write`, and/or `admin`. The scope a request requires is
derived from the route, not declared per endpoint:

| Request | Required scope |
|---|---|
| `GET`, `HEAD`, `OPTIONS` | `read` |
| `POST`, `PUT`, `PATCH`, `DELETE` | `write` |
| Any method on an administrative surface | `admin` |

Scopes escalate: `admin` implies `write` implies `read`. A handful of `POST`
routes that query rather than mutate (`/rag/query`, `/nlq/query`, `/exports/*`,
…) require only `read`.

**Reading a 403.** If the message names a *scope*, the credential is too narrow
— issue a new key with wider scopes. If it names a *role*, the user lacks
permission and a new key will not help. That distinction is invisible from the
wire, which is exactly why it belongs in SDK documentation.

Enforcement is gated by `UKIP_API_KEY_SCOPES_ENFORCED` on the server. Check
`GET /health` → `features.api_key_scopes_enforced` for a given deployment; while
it is off, scope violations are audited but not blocked.

## Stability

`openapi.json` is generated from the **full** API surface — every route the
application registers. Not all of it is a stability commitment: internal and
admin endpoints appear alongside the ones intended for integrators. Treat the
tagged public surfaces (`entities`, `analytics`, `search`, `ingestion`,
`api-keys`, `widgets`) as the supported contract, and expect the rest to change
without notice.

## Generating the clients

Both clients are generated from `openapi.json` inside pinned official Docker
images, so the toolchain is identical everywhere and no local Node/Python
install is required:

```bash
node scripts/generate-sdk.mjs              # 1. refresh sdk/openapi.json
bash scripts/generate-sdk-clients.sh       # 2. regenerate sdk/typescript + sdk/python
```

Pinned versions (in `scripts/generate-sdk-clients.sh`):

| Generator | Version | Output |
|---|---|---|
| `@hey-api/openapi-ts` | `0.99.0` | `sdk/typescript/` |
| `openapi-python-client` | `0.29.0` | `sdk/python/` |

**Why Docker instead of `npx`/`pip` directly.** On Windows `npx` fails with
`ECOMPROMISED — Lock compromised`, and adding the generators to
`frontend/package.json` regenerates `frontend/package-lock.json`, which strips
the Linux-native binaries `sharp` and friends need. A pinned Docker image gives
a clean Linux toolchain without touching either — the sanctioned path on every
platform.

Both generators are deterministic given a fixed `openapi.json` and pinned
versions (verified by regenerating twice and diffing). The Python generator's
`ruff` cache (`sdk/python/.ruff_cache/`) is the one non-deterministic artifact
and is git-ignored.

### Python fidelity note — resolved

Older FastAPI emitted `-Input`/`-Output` schema variants for Pydantic models
used as both request and response bodies. `openapi-python-client` collapses
those to one model name and skips the collisions, which left three internal
domain-admin models (`DiscourseConfig`, `DomainSchema`, `EpistemologyConfig`)
missing their `-Output` variant and the `PATCH /domains/{domain_id}/epistemology`
200 response untyped.

This note used to recommend fixing it upstream in the FastAPI schema rather
than hand-editing the client. That is effectively what happened: aligning the
image and the lock (issue #201) moved the spec to FastAPI 0.140, which no
longer splits those three models. The spec went from 192 schemas to 189 with
**zero change to the 420 operations**, and the endpoint now returns
`DomainSchema | HTTPValidationError | None` instead of `HTTPValidationError | None`.

Both clients now cover the full surface. If a future model is used as both
request and response body and FastAPI splits it again, the same collision can
reappear — regenerate and check the diff for a newly untyped response rather
than assuming parity holds.
